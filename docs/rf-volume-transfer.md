# Verified mesh mapping and sampled-volume heating transfer

Centroid deposition can leave fine transport bins without RF centroids even
when finite-size tetrahedra overlap those bins. The optional sampled transfer
uses the saved mesh to distribute a cell's integrated power across its volume.
It does not rerun Maxwell, alter the RF field or smooth/fill empty bins.

## Retry the 4x32 experiment

After transferring these changes to Linux:

```bash
cd ~/Documents/HeliconThruster
python3 -m helicon.rf.continuation \
  --rf-solution runs/rf-reference-20261027-121634/ams-main-20261102-164445/solution \
  --plasma-config config/plasma_spatial_4x32_phelps.json \
  --absorbed-power-W 100 \
  --steps 40 \
  --heating-transfer sampled \
  --transfer-samples 512 \
  --allow-exploratory-interface \
  --out runs/coarse-continuation-4x32-100W-phelps-sampled
```

Python runs once without MPI. The same flags are available on
`helicon.rf.prescribed`. The default remains `--heating-transfer centroid` for
reproducibility of old experiments. Use a new output directory on every attempt.
NumPy and SciPy are sufficient for transfer; Gmsh/DOLFINx/PETSc are not loaded.

For a transfer-only check without any plasma solve:

```bash
python3 -m helicon.rf.volume_transfer \
  --rf-solution runs/rf-reference-20261027-121634/ams-main-20261102-164445/solution \
  --plasma-config config/plasma_spatial_4x32_phelps.json \
  --samples 512 \
  --allow-exploratory-interface \
  --out runs/transfer-check-4x32
```

This leaves heating in its original RF reference-power units. It does not
normalize to 100 W. The prescribed/continuation commands perform that explicit
normalization after conservation and sampling checks pass.

## Mapping and cache

The reader supports the linear ASCII Gmsh 4.1 tetrahedra generated by this
project. Non-contiguous node tags are supported. Unsupported formats, multiple
physical regions per volume entity, missing nodes or degenerate tetrahedra fail
explicitly; no silent conversion is attempted.

Every exported owned cell, across all materials and all MPI shards, must match
exactly one mesh tetrahedron using physical region, centroid and volume. The
centroid tolerance is max(1e-12 m, 1e-10 times the largest mesh extent); volume
matching uses relative tolerance 1e-8 plus 1e-24 m3 absolute tolerance. Counts
must agree per region, and the mapping must be a bijection. Ambiguous matches,
duplicate exports and incomplete shards fail. MPI row order is never assumed
to match Gmsh order.

`transfer/mesh_mapping.npz` preserves element IDs and vertices in export order,
input hashes and matching errors. Transfer-only runs save it directly under
the output directory. For another grid with the SAME RF mesh and exports, add:

    --transfer-mapping runs/transfer-check-4x32/mesh_mapping.npz

or the corresponding continuation `transfer/mesh_mapping.npz` path. The cache
is checked against current mesh/export hashes, its payload hash, centroid and
volume agreement. It is copied into the new result; previous outputs are not
overwritten. The transfer-only command uses `--mapping` for this option.

## Deposition and acceptance

The integrated power and volume of each plasma tetrahedron are distributed
with equal-weight samples uniformly drawn in its Cartesian volume. Deterministic,
scrambled four-dimensional Sobol points are transformed to Dirichlet(1,1,1,1)
barycentric coordinates. No extra cylindrical weighting is applied: sampling
3D volume and summing azimuthally already accounts for annular geometry.
Each sample carries exactly 1/N of its tetrahedron's power and volume.

The assumption is **uniform absorption density within each RF tetrahedron**.
This retains the original integrated cell power but does not recover its
high-order RF heating variation. It is an approximate overlap integration,
not an exact tetrahedron/annulus intersection calculation.

`--transfer-samples 512` compares two nested levels, 512 and 1024 samples per
plasma tetrahedron, then uses the finer result. Allowed base levels are powers
of two from 16 to 65536. The following checks must pass before plasma solves:

- Original exported plasma power agrees with the RF summary to 1e-6 relative.
- Geometric sampled volume occupies every bin at BOTH sampling levels.
- The L1 changes in binned power and binned volume, divided by their respective
  totals, are each below `--transfer-rtol` (default 0.005 = 0.5%).
- The deposited total power still agrees with the RF summary to 1e-6 relative.

Geometric coverage is independent of deposited power: a zero-power tetrahedron
can cover a bin. Sampled volume does not prove exact geometric coverage, and
agreement between two levels is not a rigorous integration error bound. If a
check fails, retain the diagnostics and increase sampling in a NEW directory;
do not weaken the tolerance or invent values for empty bins.

`transfer/transfer_diagnostics.json` reports the mapping, coverage, empty-bin
indices, conservation, both sample counts and sampling changes. The companion
`transfer_samples.npz` saves both power and volume maps, plus grid faces. These
files remain available when a transfer gate fails. The original faceted RF
plasma volume and ideal cylindrical FV volume are reported without a hidden
volume correction.

The transfer-only check also saves its original-power `heating.npz` and source
provenance. No plasma feedback or open-boundary validation is introduced.

## Comparisons and verification

Re-run the 4x16 reference with the SAME sampled-transfer settings before
interpreting 4x16-to-4x32 differences. Comparing a centroid-deposited 4x16 run
against a sampled 4x32 run mixes a transfer-method change with grid refinement.
Also test higher sample counts when sampling differences are significant
relative to the grid changes under investigation.

Tests cover non-contiguous mesh nodes, reversed MPI export ordering, ambiguous
geometry, duplicate exports, changed volumes and stale caches. An independent
analytic tetrahedron test checks the known volume fraction above a plane;
zero-power coverage and failure-preserved reports are checked separately.

On the older local RF case
`runs/rf-compact-20261023-194156/mumps-ooc-4000-20261026-130445`, all 228249
exported cells matched uniquely; centroid error was zero and maximum relative
volume mismatch was 1.97e-14. On 4x32, every bin was sampled at both levels;
power conservation error was 8.59e-15, binned-power L1 change 1.85e-4 and
binned-volume L1 change 6.99e-4 for 512 versus 1024 samples. This is a local
transfer verification; the latest Linux RF exports still require their check.
